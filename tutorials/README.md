## Three things this tutorial does that most of the fleet's others do not

**It converts a pickled checkpoint in the runtime and says so.** The upstream file is an mmsegmentation checkpoint; Section 3 prints the static audit (the seven globals the pickle would import — four for the state dict, three that rebuild one numpy scalar in `meta` — 0 violations, the pinned audit digest) and the conversion record (112 tensors read, 14 training-only tensors and the optimizer dropped, 98 kept, the converted file's digest) before the model loads, and the provenance export records `served_from_pickle: false` and the three names bound to inert stand-ins.

**It runs the network from code it carries.** No mmcv, mmsegmentation or timm is installed; the temporal ViT encoder, the transposed-convolution neck and the FCN head come from the carried `modeling.py`, whose positional table equals the checkpoint's and whose input layout reproduces the upstream data pipeline's plain reshape — the notebook says why that layout, and not the one the axis names suggest, is the right one.

**It adapts a model that was selected on the sampled chips, and says what that means.** Every chip of the archive belongs to the split the published checkpoint's best epoch was chosen on, so the bounded head fine-tuning is a demonstration of the contract: the class-weighted validation loss falls a little, the mean IoU stays where it was, and the notebook reads the result against the majority-class baseline rather than presenting it as an improvement.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import; its only network peers are the Hugging Face Hub (the checkpoint and the tarball at immutable revisions) and PyPI. Section 2 embeds the repository's 4 modules (`modeling.py`, `metrics.py`, `pipeline.py`, `samples.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 3-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes all three entries and asserts the checkpoint's digest against the package constant; `PrithviCropPipeline.from_pretrained(weights_dir=..., report=print)` audits and converts the pickle when the safetensors file is absent, verifies it against the pinned digest, builds the vendored network and loads it strictly. The pickle is unpickled exactly once, in that conversion, through torch's weights-only loader with the meta globals bound to stand-ins, after the audit.
- **Stages (§4.1):** `fetch_sample_dataset` (the pinned tarball, extracted) / `load_byod_dataset` (sample acquisition) → `dataset_manifest` + `validate_dataset` refusal probes (validation, with the ceilings and a dataset digest) → roles by block (train / validation / test) → `pipe.evaluate` on the frozen model with the majority-class baseline (baseline) → `pipe.adapt` (bounded head fine-tuning) → `pipe.evaluate` on validation and test with the paired comparison (evaluation) → `pipe.predict` class maps (inference) → `pipe.save_artifact` → `PrithviCropPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the softmax scores are the head's outputs, labelled uncalibrated; the decision rule is the argmax with no threshold, and the notebook says any minimum-confidence rule or post-processing is the deployment's to set.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the majority-class baseline is scored on the same pixels as every model number, and every metric is labelled as pixel-pooled tutorial sample-sanity evidence from 12 test chips with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** roles come from a seeded assignment of 4 × 4-chip blocks, never from shuffling chips; validation loss selects the epoch and the test chips are used for nothing but the final evaluation; the notebook states that neighbouring blocks may share fields and that real data must be split by region; the class weights come from the upstream configuration, not from the sample. In BYOD mode the seeded split is by chip and the notebook says to group by region.
- **Ceilings (VAL6):** the chip size, the date and band counts, the value range, the label values and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user chips flow through the same validation, baseline, adaptation, evaluation, inference, export and reload cells. The expected zip layout, the label convention and the privacy guidance are stated in the Prerequisites and in Section 4, and a sample pair is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
